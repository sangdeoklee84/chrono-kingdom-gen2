6단계 제작 순서

Step-by-step

신규 스테이지 하나당 이 순서대로 진행합니다.

1
배경 분석

스테이지 배경 이미지 확인

Stage_IMG\IMG_[스테이지] NN 이름.jpg 파일을 열어
컨셉 컬러 팔레트, 주요 오브젝트, 분위기를 파악합니다.
대형 참조 시트: 스테이지 이미지_랜드마크_001~004.jpg

2
컨셉 기획

랜드마크 컨셉 3종 선정

배경에서 랜드마크로 만들 수 있는 구조물 후보를 3개 뽑습니다.
각 컨셉은 메인 오브젝트 + 베이스 소재 + 이펙트 요소로 정의하세요.

예시 — TuskGate (상아 아치), GothicArch (장미 고딕 아치), CrystalSpire (수정 첨탑)
3
앵커 준비

앵커 이미지 업로드 (스타일 레퍼런스)

스테이지 테마에 맞는 앵커 파일 2개 + landmark_base.png를 Higgsfield에 업로드합니다.
아래 앵커 테이블에서 테마별 파일을 선택하세요. 

# 한국어 경로 파일은 C:\Temp\ 에 복사 후 업로드
# PowerShell: media_upload → PUT → media_confirm
[System.IO.File]::Copy($_.FullName, "C:\Temp\anchor.png", $true)
$bytes = [System.IO.File]::ReadAllBytes("C:\Temp\anchor.png")
$wc = New-Object System.Net.WebClient
$wc.UploadData($upload_url, "PUT", $bytes)
새 세션을 열 때마다 media_id가 만료됩니다. 재업로드 필요.
4
배치 생성

generate_image_batch 실행

컨셉 3종을 한 배치에 묶어 최대 12개까지 한 번에 생성합니다.
아래 프롬프트 템플릿의 [placeholder]를 교체해 사용하세요. 

generate_image_batch(requests: [
  { index: 0, params: {
    model: "gpt_image_2_5",
    prompt: "...",
    aspect_ratio: "1:1",
    background: "transparent",
    quality: "high",
    resolution: "1k",
    medias: [{ value: media_id, role: "image_references" }, ...]
  }},
  { index: 1, params: { ... } }, // 컨셉 B
  { index: 2, params: { ... } }  // 컨셉 C
])
→ jobs_wait(jobs: [...])
→ show_generation_by_ids(jobs: [...])
5
검수

8개 항목 체크리스트 확인

결과물이 아래 스타일 규격을 모두 충족하는지 확인합니다.
통과 못 한 항목이 있으면 프롬프트를 수정해 다음 버전(vN+1)을 생성합니다.

6
최종 저장

버전 폴더 → 루트 복사

매 배치는 신규생성\vN\ 폴더에 저장합니다. 최종 확정본만 루트로 복사하세요.

# PowerShell 결과 다운로드
$wc = New-Object System.Net.WebClient
$wc.DownloadFile($result_url, "D:\경로\신규생성\v1\26A_컨셉.png")

# 최종 확정 후 루트 복사
[System.IO.File]::Copy(
  "신규생성\vN\26F_TuskGate.png",
  "stage_Landmark\26_Nest_Pantra.png",
  $true
)

검수 체크리스트

Step 5 상세

8개 항목을 순서대로 확인합니다. 하나라도 NG면 다음 버전을 생성합니다.

외곽선 — thin / fine 얇고 깔끔한 선. thick·medium-weight 표현은 AI가 과도하게 두껍게 렌더링함. ❌ v6~v12 내내 반복된 실수 — 프롬프트에 "thin/fine"을 명시하지 않으면 항상 두꺼워짐
셀쉐이딩 — 하드엣지 플랫, 3단계 Bright highlight / Mid-tone / Deep shadow. 각 존 내부는 단색 플랫 채색. ❌ 소프트 그라디언트 금지
채도 — 절제된 채도 선명하되 네온·과포화 금지. 기존 레퍼런스(11_Ice_Cave, 02_Spirit_Forest) 수준.
베이스 — 원형 디스크, 장식 없음 소재의 자연 컷오프 엣지. 금색 테두리·하트 림·데코 프레임 없어야 함. ❌ 별도 장식 테두리가 생기면 베이스가 별도 플랫폼처럼 보임
크기 리듬 — 100 : 60 : 35 반복 요소(장미, 뼈 등)는 크기 단계가 있어야 함. 모두 같은 크기면 NG.
데포르메 수준 — 3~4개 오브젝트, 단순 실루엣 기존 랜드마크 수준의 단순함. 1k 해상도에서 디테일이 과하면 NG.
외곽 확산 글로우 없음 아이콘 실루엣 전체를 감싸는 헤이즈·오라·헤일로 금지. ✅ 광원(캔들·용암·보석·눈) 주변 로컬 글로우는 허용
배경 투명 (알파) PNG 알파 채널 확인. 배경이 흰색으로 채워져 있으면 NG.

스타일 규칙

v6~v15 제작 과정에서 반복된 수정사항을 정리한 핵심 규칙입니다.

✅ 해야 할 것

  • 프롬프트에 반드시 "thin" 또는 "fine" 명시
  • 셀쉐이딩: "hard-edge flat", 3 tonal zones
  • 크기 리듬: "1 large (100%), 2 medium (60%), 2 small (35%)"
  • 뼈 볼륨: 두께/길이 비율 45%, 관절 끝 둥글게
  • 베이스: "natural material cutoff — clean, defined edge"
  • 광원 글로우: 캔들·용암·보석 인접 로컬만 허용
  • 배치마다 vN 폴더에 저장 (버전 추적)

❌ 하지 말 것

  • "thick" 또는 "medium-weight" 아웃라인
  • 소프트 그라디언트 채색
  • 네온 과포화 (neon, over-vivid)
  • 베이스에 금색 테두리·하트 림·데코 프레임
  • 아이콘 전체를 감싸는 확산 글로우·헤이즈·오라
  • 같은 크기 반복 요소 (리듬 없는 구성)
  • 최종 저장 없이 신규생성 폴더에만 남기기

Base edge is the natural material cutoff — clean, defined edge.
NO decorative border, rim, or added frame around the base perimeter.

STYLE:
- Simplified stylized cartoon art — bold rounded shapes,
  mobile game icon level of detail. Deformed cartoon proportions.
  Only 3-4 main visual elements. NOT realistic.
- Thin clean black outlines — NOT thick, NOT medium, fine lines only.
- Hard-edge flat cel-shading, 3 distinct tonal zones
  (bright highlight / mid-tone / deep shadow).
  Flat fills within each zone. NOT soft gradient.
- Controlled saturation — NOT neon, NOT over-vivid.
- No diffuse outer glow, no halo.
  Localized glow from light sources only.

Fantasy RPG mobile game icon art. Circular composition, 75-80% frame fill.
